# CBC/CBE Academic Module — Implementation Analysis

> Required pre-implementation analysis (per the implementation prompt, section 91).
> This documents the **existing** system as inspected during Phase 1 discovery, and the
> **proposed** CBC/CBE architecture, migration strategy, and blast radius before any
> entity is written.

Source of truth for curriculum facts: **KICD / KNEC / Ministry of Education** official
documents only. Where a rule is uncertain or version-specific, it is modelled as
**configuration/reference data**, never hard-coded in business logic.

---

## 1. Existing academic architecture

Two coexisting layers under `com.EduePoa.EP`:

- **`Scoring`** (older): `StudentsScore`, `ExamType`, `ExamTypeGrading`, `ExamService`,
  `ExamController1` (`api/v1/exams/`). Raw marks + a legacy A–E/points grading table.
- **`academics`** (newer, the target package): `controller / dto / entity / repository /
  service / service.impl`. Already contains `AcademicSubject`, `ClassSubjectAssignment`,
  `CbcGradeResult`, `Attendance`, plus a first-cut `CbcCalculatorServiceImpl`.

Flow (traced): `Controller` → `*Request` DTO → `Service`/`*ServiceImpl` →
`TenantAwareRepository` (auto tenant filter) → `TenantScopedEntity` subclass → `CustomResponse<T>`
returned via `ResponseEntity.status(res.getStatusCode()).body(res)`.

## 2. Existing database relationships

- `StudentsScore` → `Student`, `Grade`, `AcademicSubject`, `ExamType`, `User` (teacher/approver);
  `Term` enum column; `java.time.Year`. No explicit unique constraint (dedup done in service).
- `CbcGradeResult` → `Student`, `AcademicSubject`; unique `{student_id, academic_subject_id, term, year}`.
- `ClassSubjectAssignment` → `Grade`, `AcademicSubject`; unique `{grade_id, academic_subject_id, year}`.
- `Attendance` → `Student`, `Grade`; unique `{student_id, date}`.
- `Grade` 1—* `GradeStream`; `Student` → `Grade`, `GradeStream` (+ denormalized name strings).
- Schema is generated by Hibernate `ddl-auto=update` (MariaDB). **No Flyway/Liquibase.**
  New `@Entity` classes are auto-created on startup.

## 3. Existing scoring architecture

- `StudentsScore.examScore` (`Double`) is the raw mark; `ExamType` holds `maxScore/minScore`.
- `CbcCalculatorServiceImpl` averages `examScore` per `student → academicSubject`, then maps to
  a CBC level via **hard-coded thresholds** `>=80/50/30` and hard-coded labels. This is exactly
  what the prompt forbids and what the new engine replaces.
- `ExamTypeGrading` (legacy points/remarks bands) is **orphaned**: referenced only by `ExamService`,
  never by the CBC path, and its `examType` FK is never set (pre-existing bug).

## 4. Existing curriculum-related functionality

- Curriculum is currently just a flat `AcademicSubject` list (name, code, free-text `learningArea`,
  `isCbcCore`). **No** curriculum versioning, education levels, strands, sub-strands, learning
  outcomes, competencies, values, PCIs, assessment frameworks, or performance-level catalogue.

## 5. Existing permissions

Enforced via `@PreAuthorize("hasPermission(null, '<perm:string>')")` + `CustomPermissionEvaluator`
reading `user.getRole().getRolePermissions()`. Relevant existing perms: `SUBJECT_CREATE/READ`,
`EXAM_GRADE`, `EXAM_MARK_ENTER`, `CAT_MARK_ENTER`, `REPORT_GENERATE`, `GRADE_APPROVE_HOD/DEAN`,
`GRADE_PUBLISH`, `TRANSCRIPT_GENERATE`, `ACADEMIC_YEAR_MANAGE`, `ATTENDANCE_MARK/READ`.
`AttendanceController` is the secured reference; the exam & CBC controllers are currently unsecured.

## 6. Existing seed mechanisms

- `SchemaUpdater` `@Order(HIGHEST_PRECEDENCE)` — `JdbcTemplate` widens `role_permissions.permission`
  to `VARCHAR(50)` so new enum permission strings fit.
- `CreateAdmin` `@Order(10)` `ApplicationRunner` — seeds default tenant `bureti-high`, roles, admins.
  Pattern: `try { TenantContext.setCurrentTenant(tenant); ... } finally { TenantContext.clear(); }`
  with existence-guard idempotency.
- `TenantProvisioningService` — per-tenant roles/config on tenant creation.

## 7. Existing tenant-scoping mechanism

Entities extend `TenantScopedEntity` (`@MappedSuperclass`, `@FilterDef tenantFilter`, `tenant_id`
column, `TenantEntityListener` that auto-sets `tenantId` on persist). Each concrete entity **repeats**
`@Filter(name="tenantFilter", condition="tenant_id = :tenantId AND tenant_id IS NOT NULL AND tenant_id != ''")`.
Repositories extend `TenantAwareRepository<T, Long>`; the Hibernate filter is enabled per-request by
`HibernateFilterInterceptor`. **All new tenant-owned entities follow this exact convention.**

## 8. Existing API consumers

- `api/v1/exams/*` (ExamController1), `api/v1/academics/subjects/*`, `api/v1/academics/cbc/*`,
  `api/v1/academics/attendance/*`, class-subject + upload-marks endpoints.
- The frontend consumes `CustomResponse<T>`. **Contract must not change**; new endpoints are additive.

## 9. Proposed migration strategy

- **Additive first.** Introduce the curriculum + assessment-framework model as new tables. Do not
  drop or rename existing columns. `ddl-auto=update` adds new tables/nullable columns safely.
- **`StudentsScore`** is retained as the raw-score source. Add **nullable** `rawScore` /
  `maximumScore` / `curriculumVersion` alongside the existing `examScore` (kept for back-compat).
  The new engine prefers `rawScore` and falls back to `examScore`.
- **`CbcGradeResult`** is retained; add **nullable** columns (`performanceLevel` FK, points,
  normalized score, `assessmentFrameworkId`, `curriculumVersionId`, teacher comment) so historical
  rows keep `cbcLevel/cbcLabel`. Existing unique constraint preserved.
- **`ExamTypeGrading`** → marked `@Deprecated` with a documented note; **not deleted** (orphaned but
  referenced by `ExamService` DTOs). Removed only after a dependency review in a later phase.
- **Term** stays an enum for now; a single `TermResolver` service centralizes the duplicated
  `resolveTermById` switch, leaving a clear path to a future `AcademicYear`/`AcademicTerm` model.
- Curriculum reference data is **externalized to JSON** and seeded idempotently per tenant.

## 10. Proposed CBC architecture

Curriculum hierarchy (new entities, all tenant-scoped, all carrying `curriculumVersion`):

```
CurriculumVersion → EducationLevel → Grade(existing, linked via GradeLevelMapping)
                  → LearningArea → Strand → SubStrand → SpecificLearningOutcome
                                                        → InquiryQuestion
                                                        → LearningExperience
Metadata catalogues: CoreCompetency, CbcValue, PertinentContemporaryIssue
Assessment: AssessmentFramework → PerformanceLevel (bands, points), AssessmentType,
            Assessment → AssessmentComponent → StudentsScore(raw) → CbcGradeResult
Evidence: CompetencyEvidence (learner × competency × evidence)
Reporting: StudentTermSummary + ReportCardDto (assembled, not a table dependency)
Config: SchoolCurriculumConfiguration, RankingPolicy
```

Services (single responsibility, no god-class): `CurriculumService`, `AssessmentFrameworkService`,
`PerformanceLevelService`, `AssessmentService`, `AssessmentCalculationService`,
`CompetencyAssessmentService`, `RankingService`, `ReportCardService`, `TermResolver`,
`CurriculumSeeder`.

Calculation is **framework-driven**: resolve the `AssessmentFramework` → normalize raw/max →
apply component weights → resolve `PerformanceLevel` by configured score band → persist result with
the framework/band ids used (reproducibility). KJSEA EE1–BE2 bands + points live as data in the
KJSEA framework, **not** in code.

## 11. Potential breaking changes

- **None intended.** Risks and mitigations:
  - New nullable columns on `StudentsScore`/`CbcGradeResult` — safe under `ddl-auto=update`.
  - New permission enum values — `SchemaUpdater` already widens the column; no action needed.
  - New `@Order` seeder must run **after** `CreateAdmin` (tenant must exist first) → `@Order(30)`.
  - Centralizing `resolveTermById` changes internals of 3 services but not their behavior/DTOs.

## 12. Files that will be created (new)

Curriculum entities/repos: `CurriculumVersion`, `EducationLevel`, `GradeLevelMapping`, `LearningArea`,
`Strand`, `SubStrand`, `SpecificLearningOutcome`, `InquiryQuestion`, `LearningExperience`,
`CoreCompetency`, `CbcValue`, `PertinentContemporaryIssue`.
Assessment: `AssessmentFramework`, `AssessmentType`, `PerformanceLevel`, `Assessment`,
`AssessmentComponent`, `CompetencyEvidence`, `StudentTermSummary`, `RankingPolicy`,
`SchoolCurriculumConfiguration`.
Enums: `CbcEducationLevel`, `PerformanceMethod`/`AssessmentMethod`, `CurriculumSource`,
`ResultStatus`, `RankingScope`, `CompetencyLevel`.
Services + impls (listed in §10), controllers (`CurriculumController`, `CompetencyController`,
`AssessmentFrameworkController`, `ReportCardController`), DTOs (per §72), `TermResolver`,
`CurriculumSeeder` + JSON reference data under `resources/curriculum/`, and tests.

## 13. Files that will be modified

- `Permissions.java` — add `CURRICULUM_READ/MANAGE`, `ASSESSMENT_CREATE/READ/MANAGE`,
  `COMPETENCY_ASSESS`, `RESULT_AMEND`, `LEARNING_OUTCOME_READ`.
- `StudentsScore.java` — add nullable `rawScore`, `maximumScore`, `curriculumVersion`, `resultStatus`.
- `CbcGradeResult.java` — add nullable `performanceLevel`, points, normalized score, framework/version refs, comment.
- `CbcCalculatorServiceImpl.java` — replace hard-coded thresholds with framework-driven resolution
  (delegates to `AssessmentCalculationService` + `PerformanceLevelService`).
- `ExamService`, `UploadMarksServiceImpl` — use shared `TermResolver`.
- `TenantProvisioningService` / a new seeder — grant CBC permissions to appropriate roles + seed curriculum.

## 14. Files that must NOT be modified

- `TenantScopedEntity`, `TenantAwareRepository`, `TenantContext`, `TenantEntityListener`,
  `HibernateFilterInterceptor` (tenancy core — reuse, never fork).
- `CustomResponse` (response contract).
- `CustomPermissionEvaluator` / security config (reuse existing enforcement).
- Existing DTO shapes consumed by the frontend (extend additively, never break).
- `ExamTypeGrading` is **deprecated, not deleted**, in this phase.

## Curriculum facts & sources (no invented rules)

- Seven CBC core competencies — communication & collaboration; critical thinking & problem solving;
  creativity & imagination; citizenship; digital literacy; learning to learn; self-efficacy.
  Source: [KICD Volume 3 Curriculum Designs](https://kicd.ac.ke/wp-content/uploads/2017/10/Volume-3-curriculum-designs-September-2017.pdf),
  [Basic Education Curriculum Framework 2019](https://kicd.ac.ke/wp-content/uploads/2019/08/BASIC-EDUCATION-CURRICULUM-FRAMEWORK-2019.pdf).
- KJSEA performance levels (EE1–BE2) and points are taken verbatim from the implementation prompt's
  published table and stored as data in the KJSEA `AssessmentFramework`, not in code.
- Where an official rule is version-specific or uncertain, it is represented as configuration and
  attached to a `CurriculumVersion` / `AssessmentFramework` so future KICD/KNEC changes need data
  edits, not code changes.

## Migration decisions (Phase 10 — implemented)

- **StudentsScore**: extended with nullable `rawScore`, `maximumScore`, `curriculumVersion`,
  `assessment`, `resultStatus`; legacy `examScore` retained. `effectiveRawScore()` prefers the new
  field. No columns renamed or dropped. Existing consumers (ExamService, UploadMarks) unchanged.
- **CbcGradeResult**: extended with nullable `normalizedScore`, `performanceLevel`,
  `performancePoints`, `teacherComment`, `assessmentFrameworkId`, `curriculumVersionId`,
  `calculationVersion`; legacy `averageScore`/`cbcLevel`/`cbcLabel` retained for back-compat.
- **CbcCalculatorServiceImpl**: rewritten to be framework-driven. Hard-coded 80/50/30 thresholds
  removed. A documented generic fallback (76/51/26) is used ONLY when no assessment framework is
  configured, so the endpoint still works before curriculum data is seeded; once the KJSEA/INTERNAL
  frameworks are seeded, configured `PerformanceLevel` bands are authoritative.
- **ExamTypeGrading**: marked `@Deprecated` (not deleted). Still referenced only by `ExamService`
  and its DTOs. Removal deferred to a future dependency review once the UI no longer calls the
  legacy grading-criteria endpoints.
- **Term resolution**: the duplicated `resolveTermById` switch in `ExamService` and
  `UploadMarksServiceImpl` now delegates to the shared `TermResolver`; `CbcCalculatorServiceImpl`
  uses `TermResolver` directly. The private methods were kept as thin delegators to avoid touching
  call sites. Clear path to a future persisted `AcademicYear`/`AcademicTerm` model.
- **Tenant provisioning**: `TenantProvisioningService.provisionTenant` now calls
  `CurriculumSeeder.seedForTenant` so new tenants automatically receive the CBC catalogue and
  frameworks (idempotent). `School_Admin` already receives all permissions (including new CBC ones).
- **Historical integrity**: results store the `curriculumVersionId`/`assessmentFrameworkId` used;
  curriculum reference data is soft-statused (DRAFT/ACTIVE/DEPRECATED/ARCHIVED) rather than deleted,
  so introducing a new curriculum version does not mutate historical rows.

## Architecture diagram

```
Curriculum (versioned reference data)
  CurriculumVersion → EducationLevel → LearningArea → Strand → SubStrand → SpecificLearningOutcome → InquiryQuestion
  CurriculumVersion → GradeLevelMapping (Grade ↔ EducationLevel, data-driven)
  CurriculumVersion → CoreCompetency, CbcValue, PertinentContemporaryIssue
  LearningArea → LearningExperience

Assessment framework (configurable, no hard-coded thresholds)
  AssessmentFramework → PerformanceLevel (bands + points), AssessmentComponent (weights), AssessmentType
  Assessment → AssessmentFramework + LearningArea/Strand/SubStrand/SpecificLearningOutcome

Capture
  StudentsScore (rawScore/maximumScore, legacy examScore) → Assessment
  CompetencyEvidence → CoreCompetency + PerformanceLevel (evidence-based, not derived from marks)

Results engine (framework-driven)
  CbcCalculatorServiceImpl
    → FrameworkResolutionService  (which framework applies to the grade)
    → AssessmentCalculationService (normalize raw/max, weight components)
    → PerformanceLevelService      (resolve configured band; validate no overlaps)
    → CbcGradeResult (stores frameworkId/versionId + calculationVersion for reproducibility)

Reporting
  ReportCardService → CbcGradeResult + CompetencyEvidence + Attendance + RankingService(optional)
                    → StudentTermSummary + ReportCardDto (PDF-ready, stage-aware)

Cross-cutting
  All tenant-owned entities extend TenantScopedEntity (tenantFilter); repos extend TenantAwareRepository.
  CurriculumSeeder (idempotent, per-tenant, JSON reference data) runs at startup and on tenant provisioning.
```

## Verification summary (Phase 11)

- `AssessmentCalculationServiceImplTest` — normalization (42/50 = 84%), weighted average (CAT/End-Term), validation.
- `PerformanceLevelServiceImplTest` — KJSEA EE1–BE2 resolution + points (8..1), inclusive boundaries, band validation (overlap/range/min>max rejected).
- `TermResolverTest` — centralized term resolution.
- `CbcCalculatorServiceImplTest` — section-80 end-to-end: Grade 7 Mathematics, raw 42/max 50 → 84% → framework resolves the level (level asserted from configuration, not hard-coded in the calculator).

Full `./mvnw test` suite passes (including pre-existing multi-tenancy/reports tests and the Spring context test), confirming no regressions.
